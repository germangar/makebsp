===========================================================================
PROPOSAL: Lightmap Intensity Normalization (-lightmaprange)
===========================================================================

INTRODUCTION
------------
This task involves implementing a high-dynamic range (HDR) lighting normalization 
pass in the 'makebsp' lighting compiler. 

Currently, the compiler uses a 32-bit floating-point pipeline for all 
calculations. However, when saving to legacy BSP formats (IBSP/FBSP), these 
values are down-converted to 8-bit integers (0-255). Any light value exceeding 
255.0 is currently clamped, leading to "blown out" white areas where 
high-intensity light sources or multiple radiosity bounces accumulate.

RESEARCH FINDINGS
-----------------
We audited the Q3Map2 reference source code to see if it injected a key named 
'_lightingIntensity' into the worldspawn to solve this. Our audit of 
q3map2_reference (GtkRadiant branch) confirmed that this key is NOT present in 
standard Q3Map2. It appears to be a feature of specific engine forks or custom 
compiler branches.

GOAL
----
Implement a new switch '-lightmaprange' that finds the absolute maximum 
intensity of any R, G, or B channel across the entire map. Instead of 
clamping at 255, the compiler will use this maximum to proportionally scale 
all lightmap pixels into the 0-255 range. To allow the game engine to 
reconstruct the original intensities, the scale factor used will be 
recorded in the 'worldspawn' entity.

DETAILED IMPLEMENTATION PLAN
----------------------------

1. GLOBAL STATE (common/lightdata.h & common/lightdata.c)
   - Add 'qboolean lightmapRange' (default qfalse) to track if the switch is active.
   - Add 'float maxLightIntensity' (default 0.0f) to store the peak channel value found.
   - Implement a helper: 'void UpdateMaxIntensity(const float *color, int count)'. 
     This should iterate through 'count' floats and update 'maxLightIntensity' 
     if any value is higher.

2. COMMAND LINE (light/main.c)
   - Add parsing for '-lightmaprange' in the main loop.
   - Update usage text to explain that this enables HDR normalization via worldspawn.

3. INTENSITY TRACKING (Accumulation Points)
   - Direct Lighting: In 'light/light.c' (LightMain), after the direct 
     lighting pass completes, scan the 'lightFloats' buffer.
   - Radiosity: In 'light/radiosity.c' (RadiosityMerge), scan the 
     'accumRadiosityFloats' buffer before or during its merge into 
     'lightFloats'.
   - Note: Tracking during these stages is more cache-efficient than a 
     full dedicated scan at the end.

4. DOWN-CONVERSION & INJECTION (common/lightdata.c)
   - In 'DownConvertLightingData()', check if 'lightmapRange' is true.
   - If maxLightIntensity > 255.0:
     a. Calculate the peak value among all surfaces (including grid lighting 
        and vertex colors).
     b. Calculate the scale factor. If we want 'float_val = byte_val * factor', 
        then factor = maxLightIntensity / 255.0.
     c. Inject this into worldspawn: 
        'SetKeyValue(&entities[0], "_lightingIntensity", va("%f", factor));'
     d. Pass this scale factor to 'InternalColorToBytes'.
   - Update 'InternalColorToBytes' to perform: 
     'sample[i] /= (maxLightIntensity / 255.0f)' instead of clamping at 255.

5. VERIFICATION
   - Use a test map with intentionally high-intensity lights (e.g. intensity 2000).
   - Check 'bspinfo' or a text editor to ensure '_lightingIntensity' appears 
     in the worldspawn entity string.
   - Verify that the "white out" areas now show color detail, albeit darker if 
     the engine isn't yet compensating for the scale.
