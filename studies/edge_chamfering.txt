==============================================================================
  BSP PLANAR SURFACE EDGE CHAMFERING
  Implementation Design Document (Audited & Verified)
==============================================================================

OVERVIEW
--------
This feature inserts "support edges" (also called holding edges or a face-level
chamfer with custom normals) into planar brush surfaces at sharp angle
intersections. The goal is to smooth the harsh lighting transitions at wall/floor
and wall/wall corners by blending vertex normals across a thin geometric strip,
without any change to the physical collision or BSP tree.

This is the same hard-surface modelling technique used to make sharp edges catch
highlights naturally. A tiny strip of geometry at the corner transitions the
vertex normal from the flat face normal to an averaged "corner" normal, making
the lighting engine compute a smooth gradient at the edge instead of an abrupt
discontinuity.

==============================================================================
[CRITICAL ARCHITECTURAL RULE: V3 NORMAL BENDING ONLY]

*** NOTE FROM THE USER (READ CAREFULLY) ***
We CAN'T modify the geometry boundaries. We can make subdivisions in the
planar surfaces, but NOT move any of their boundary edges. Creating true
geometric diagonal bevels would create holes in the geometry where this
corner meets a perpendicular plane, like a wall corner meeting a floor.
We can only manipulate the normals and create edge subdivisions, but
nothing else!

NOTE: The original theoretical approach described in this document (V1/V2)
attempted to create a true geometric bevel (physically removing the sharp
corner and bridging the gap with a diagonal polygon). This approach was 
completely discarded because it physically shrinks the structural geometry,
causing holes and unacceptable geometric discrepancies.

The final implemented architecture (V3) uses **Normal Bending**.
Instead of cutting off the corner, the flat faces are subdivided into an 
inner body and a border strip. The border strip connects the shrunk inner 
body back to the ORIGINAL geometric corner. The original sharp corner is 
fully preserved geometrically without moving boundary edges, but the vertices
on the strip receive blended normals to create an optical illusion of a bevel.

==============================================================================
1. DATA STRUCTURES
==============================================================================

drawVert_t (common/qfiles.h)
----------------------------
    vec3_t  xyz;            // 3D world-space position
    float   st[2];          // texture UV coordinates
    float   lightmap[4][2]; // lightmap UV channels
    vec3_t  normal;         // vertex normal (THIS IS WHAT WE MODIFY)
    byte    color[4][4];    // vertex color channels

mapDrawSurface_t (q3map/qbsp.h)
--------------------------------
Key fields at injection point:
    shaderInfo_t    *shaderInfo;
    side_t          *side;
    int              numVerts;
    drawVert_t      *verts;
    int              numIndexes;    // == 0, no index buffer yet

CRITICAL: `verts` is an ORDERED LOOP. Vertices 0..N-1 define the polygon edges
as: edge(0->1), edge(1->2), ..., edge(N-1->0). There is no index buffer. This
polygon is a flat convex N-gon lying exactly on the brush plane. Triangulation
happens implicitly later inside `SurfaceAsTristrip()` for brush surfaces.


==============================================================================
2. PIPELINE POSITION (AUDIT)
==============================================================================

In both ProcessWorldModel() and ProcessSubModel() (q3map/bsp.c), the pipeline
runs in this order:

    ClipSidesIntoTree()         <- brush sides clipped into BSP, surfaces born
    FogDrawSurfs()
    SubdivideDrawSurfs()
    MergeSides()
                                *** OUR INJECTION POINT ***
    ChamferSurfaceEdges()       <- [NEW] Runs BEFORE FixTJunctions
    FixTJunctions()             <- T-junction vertices inserted
    MakeEntityDecals()
    AllocateLightmaps()

WHY BEFORE FixTJunctions:
`FixTJunctions` inserts extra collinear vertices along edges wherever adjacent
surfaces required splits. This fractures pristine structural edges into tiny
segments. If we attempt to chamfer AFTER `FixTJunctions`, the algorithm has to
deal with fragmented chains, causing asymmetric tearing and malformed strips.
By running `ChamferSurfaceEdges` FIRST, we operate on perfectly intact, pristine
brush polygons. Once we create our clean inner bodies and chamfer strips,
`FixTJunctions` runs natively on top of our new subdivisions and elegantly sews
up any remaining T-junctions perfectly.


==============================================================================
3. THE SURFACE ADJACENCY GRAPH (CORE FOUNDATION)
==============================================================================

To avoid an O(N^2) loop when searching for adjacent surfaces, we first build a
Surface Adjacency Graph inside `ChamferSurfaceEdges`.

    typedef struct surfaceNeighbor_s {
        int neighborSurfaceNum;
        int sharedChainIndicesA[MAX_SURFACE_VERTS];
        int sharedChainIndicesB[MAX_SURFACE_VERTS];
        int sharedChainLen;
        struct surfaceNeighbor_s *next;
    } surfaceNeighbor_t;

    surfaceNeighbor_t *surfaceNeighbors[MAX_MAP_DRAW_SURFS];

`BuildSurfaceAdjacencyGraph(e)` compares pristine vertex positions to find shared
collinear chains and registers bidirectional links.


==============================================================================
4. CORNER DETECTION & SKIP CONDITIONS
==============================================================================

Two touching surfaces qualify for chamfering at their shared edge if:
    DotProduct(normalA, normalB) < 0.866f (angle is sharper than ~30 degrees)
    DotProduct(normalA, normalB) > -0.866f (avoids processing opposing faces)

Skip Conditions:
  - Patch surfaces or miscModel surfaces.
  - Surfaces lacking `ds->side`.
  - Flare surfaces.
  - Surfaces with SURF_NODRAW, SURF_SKY, or SURF_NOLIGHTMAP flags.

ADAPTIVE CHAMFER WIDTH & SAFEGUARDS (10x RATIO)
-----------------------------------------------
To prevent inverted geometry or Z-fighting when a face is too narrow or small to
support the configured `chamfer_global_width`, each surface calculates an adaptive
safe width in Pass 1:
1. Minimum Edge Calculation: Iterate all vertices to find the shortest geometric
   edge length (`min_edge`).
2. 10x Ratio Heuristic: The surface must be at least 10 times larger than the
   chamfer width (`required_space = 10.0f * chamfer_global_width`).
   If `min_edge < required_space`, we scale the chamfer width down proportionally
   to maintain the exact 10x ratio (`surface_chamfer_width = min_edge / 10.0f`).
3. Hard Safeguard: If after scaling down, `surface_chamfer_width < 1.0f`, the face
   is too small to safely chamfer. The surface is skipped entirely (`continue`),
   leaving it untouched and safe.


==============================================================================
5. THE POLYGON INSET (2D LINE INTERSECTION MATH)
==============================================================================

The core math relies on shrinking a face inward perfectly. At any polygon
corner (where two edges meet), the new inset vertex MUST be the mathematical
intersection of the two perpendicular inset lines (a mitre joint). If we simply
offset a corner along its normal, it would tear apart at coplanar seams.

For each vertex `v` and its adjacent edges `prev` and `next`:
1. Calculate edge directions: `edgeDir = normalize(next - v)`.
2. Calculate perpendicular inset direction: `insetDir = CrossProduct(edgeDir, faceNormal)`.
3. Shift the edges inward: `VectorMA(v, chamferWidth, insetDir, edgeLineOrigin)`.
4. Perform 2D Line-Line Intersection using the dot-product determinant method:
   `det = a*c - b*b`
   If `fabs(det) > 0.001f` (edges are not parallel):
       Compute standard intersection `dist` and find the mitre point.
   Else (edges are near-parallel, e.g. coplanar seams):
       Just offset perpendicularly using `VectorMA(v, chamferWidth, insetDir)`.
5. Clamp extreme mitre movements to `chamferWidth * 4.0f` to prevent runaway
   spikes at highly acute angles.


==============================================================================
6. THE 3-PASS REBUILD ARCHITECTURE
==============================================================================

The `ChamferSurfaceEdges` function operates in 3 strictly separated passes over
all draw surfaces in the entity. This prevents consecutive modifications from
corrupting shared vertex positions.

PASS 1: COMPUTE INNER BODIES (INSETS & DELTA-UVs)
-------------------------------------------------
For every candidate surface `dsA`, we scan all its neighbors.
If an edge qualifies for chamfering, we flag it.
When allocating `globalInsets[i]`, we use `memcpy` to copy the entire `dsA->verts`
array. This ensures every inset vertex inherits the original `.st`, `.color`,
`.normal`, and scratch variables.
We call `ComputeAllInsets()` to trace the geometric border of the shrunk inner
polygon, which overwrites `.xyz` in `globalInsets[i]`.
Finally, we loop through all vertices and call `ShiftVertexUV(...)` to calculate
the exact linear texture coordinate shift ($\Delta st$) corresponding to the spatial
displacement ($\Delta xyz = new\_xyz - old\_xyz$).
The original geometry is NOT modified yet.

PASS 2: GENERATE SUBDIVISION STRIPS
-----------------------------------
For every surface with computed `globalInsets`, we spawn new `mapDrawSurface_t`
strips to fill the gap.
For every chamfered edge chain:
- We allocate a new strip surface with `chainLen * 2` vertices.
- We copy properties (shader, plane, side) from the parent surface.
- The outer boundary vertices (`strip->verts[k]`) receive `dsA->verts[vIdx]`
  (original corner `.xyz` and `.st`) with `blendedNormal`.
- The inner boundary vertices (`strip->verts[innerSlot]`) receive `globalInsets[i][vIdx]`
  (inset `.xyz` and shifted `.st`) with flat `faceNormal`.
- This ensures textures bridge smoothly across the bevel strip without stretching.

PASS 3: SHRINK INNER BODIES
---------------------------
Finally, we overwrite both the coordinates (`dsA->verts[v].xyz`) and texture UVs
(`dsA->verts[v].st`) of the original large structural face with `globalInsets[i][v]`.
The original face is now safely shrunk, perfectly flat, and its textures remain
locked in 3D world space without sliding or distorting.

**Note on Pass 3 Bug Fix:** Previously, Pass 3 guarded updates with:
`if (VectorLength(globalInsets[i][v].normal) > 0.1f)`
Because `ComputeAllInsets()` only computes `.xyz` and leaves `.normal` at `{0,0,0}`,
this condition evaluated to `0.0f > 0.1f` (always false), leaving the original
surfaces completely untouched and Z-fighting with the strips. This check was removed
so that every vertex of the inner body is reliably overwritten with its inset data.


==============================================================================
7. PERIMETER WINDING ORDER (THE BOW-TIE BUG FIX)
==============================================================================

During implementation, long strips turned into self-intersecting "bow-ties" or
collapsed into single diagonal triangles.

Because we assign `strip->side = dsA->side`, the engine treats the strip as a
structural brush polygon and passes it to `SurfaceAsTristrip`.
`SurfaceAsTristrip` THROWS AWAY any explicit `strip->indexes` we provide and
attempts to implicitly auto-triangulate the quad by walking its perimeter.

If vertices are laid out as `[Outer0, Outer1, Inner0, Inner1]`, they trace a
figure-8 bow-tie. To fix this, we MUST lay out the strip vertices so they trace
a contiguous, closed outer perimeter loop.

**Correct Vertex Layout Pseudo-Code (from Pass 2):**
```c
strip->numVerts = chainLen * 2;
strip->verts = malloc(strip->numVerts * sizeof(drawVert_t));
strip->numIndexes = 0; // SurfaceAsTristrip generates indexes automatically

for (int k = 0; k < chainLen; k++) {
    int vIdx = chain[k];

    // Outer edge: forward order [0..chainLen-1]
    strip->verts[k] = dsA->verts[vIdx];
    VectorCopy(blendedNormal, strip->verts[k].normal);

    // Inner edge: REVERSE order [chainLen..2*chainLen-1]
    // Reversing closes the perimeter: last outer -> first inner
    int innerSlot = chainLen + (chainLen - 1 - k);
    strip->verts[innerSlot] = globalInsets[i][vIdx];
    VectorCopy(faceNormal, strip->verts[innerSlot].normal);
}
```
This perfectly forms an `OuterA -> OuterB -> InnerB -> InnerA` clockwise perimeter.
`SurfaceAsTristrip` natively parses this and auto-triangulates the strip flawlessly.


==============================================================================
8. TEXTURE COORDINATE PRESERVATION (DELTA-UV SHIFTING)
==============================================================================

When vertex world positions (`.xyz`) shift inward without updating texture UV
coordinates (`.st`), texture mapping distorts severely:
1. **On Chamfer Strips:** Outer and inner vertices share identical `.st`, causing
   the texture to stretch infinitely across the width of the bevel (horizontal smearing).
2. **On Shrunk Faces:** Moving the outer border inward while retaining old `.st`
   compresses and shifts the texture across the main face.

**The Integer Shift Trap (Why Absolute UVs Fail):**
In `q3map/surface.c`, when `DrawSurfaceForSide` creates a brush face, it calculates
raw texture coordinates and then applies an integer normalization step:
```c
mins[0] = floor(mins[0]);
mins[1] = floor(mins[1]);
for (i = 0; i < w->numpoints; i++) {
    ds->verts[i].st[0] -= mins[0];
    ds->verts[i].st[1] -= mins[1];
}
```
Because textures wrap every 1.0 unit, subtracting integer multiples keeps floating-point
numbers small and precise without altering visual rendering. If we recomputed absolute
UVs from raw world coordinates on inner strip vertices without applying that exact same
integer shift, outer and inner vertices on a strip would suffer an integer mismatch
(e.g., outer `.st = 0.2`, inner `.st = 5.15`), causing textures to wrap 5 times across
a 2-unit bevel!

**The Delta-UV Solution:**
Because texture projection on a planar face is an affine linear equation ($f(x) = M \cdot x + C$),
the derivative is constant ($f(x + \Delta x) - f(x) = M \cdot \Delta x$). Any constant
integer normalization shifts or origin offsets ($C$) completely cancel out!

We calculate the **Delta-UV** ($\Delta st$) directly from spatial displacement
($\Delta xyz = new\_xyz - old\_xyz$) using the native engine projection formulas,
and add it directly to `old_st`.

**Exact Implementation Pseudo-Code (`q3map/tjunction.c`):**
```c
static void ShiftVertexUV(mapDrawSurface_t *ds, drawVert_t *dv, const vec3_t old_xyz, const vec3_t new_xyz)
{
    side_t *s = ds->side;
    shaderInfo_t *si = ds->shaderInfo;
    if (!s || !si) return;

    vec3_t delta;
    VectorSubtract(new_xyz, old_xyz, delta);
    if (VectorLength(delta) < 0.001f) return; // No movement, no UV change

    if (g_bBrushPrimit == BPRIMIT_OLDBRUSHES)
    {
        if (si->width && si->height) {
            dv->st[0] += DotProduct(s->vecs[0], delta) / si->width;
            dv->st[1] += DotProduct(s->vecs[1], delta) / si->height;
        }
    }
    else
    {
        vec3_t texX, texY;
        ComputeAxisBase(mapplanes[s->planenum].normal, texX, texY);
        float dx = DotProduct(delta, texX);
        float dy = DotProduct(delta, texY);
        dv->st[0] += s->texMat[0][0] * dx + s->texMat[0][1] * dy;
        dv->st[1] += s->texMat[1][0] * dx + s->texMat[1][1] * dy;
    }
}
```
By invoking `ShiftVertexUV` during Pass 1 on `globalInsets[i]`, every inset vertex
gains exact, continuous texture coordinates that propagate cleanly to both Pass 2
(strip inner edges) and Pass 3 (shrunk main faces).

9. KNOWN EDGE CASES & ERRATA
==============================================================================

A. Triangle Stretching to Origin (0,0,0)
   DrawSurfaces created via `AllocDrawSurf()` need properly allocated `verts`
   arrays using `malloc`. Leaving them unallocated caused out-of-bounds zero
   memory reads.

B. Splits on Coplanar Surfaces
   Chamfer strips were originally ripping open planar seams on floors.
   Added a `CHAMFER_ANGLE_THRESHOLD` dot-product check (`> 0.866f`). Perfectly
   flat adjoining polygons are now completely skipped.

C. Z-Fighting Avoidance
   The algorithm achieves perfectly flush coplanar strips by strictly shrinking
   the parent face in Pass 3, rather than spawning strips blindly on top of the
   existing geometry. Because they never overlap physically, Z-fighting is avoided.
   (The inner border of the strip shares the exact same coordinates as the outer
   border of the shrunk parent face).

D. Pass 3 Normal Length Guard Removal
   Previously, Pass 3 guarded shrinking with `if (VectorLength(globalInsets[i][v].normal) > 0.1f)`.
   Because `ComputeAllInsets()` leaves `.normal` at zero, this prevented original
   faces from shrinking. Removing this guard allowed clean geometric reduction.

E. Texture Integer Wrapping Trap (Delta-UV)
   Direct world-space UV recomputation conflicts with `surface.c` integer UV
   normalization (`floor(mins)`), causing multi-wrap texture distortion on strips.
   Using Delta-UV (`new_st = old_st + M * delta_xyz`) completely bypasses integer
   offsets and guarantees seamless texture continuity.

F. Inverted Polygons on Narrow Faces
   Applying a uniform chamfer width to very small or thin faces causes the inset
   lines to cross, inverting the polygon and causing Z-fighting/holes. Added a
   10x Ratio safeguard (`surface_chamfer_width = min_edge / 10.0f`) that dynamically
   scales down the bevel width or aborts (`< 1.0f`) on small geometry.

G. Backside T-Junction Chamfers (ClassifySurfaceSide)
   Faces touching the backside of another face could falsely chamfer if they formed
   a 90-degree angle. Added `ClassifySurfaceSide` to evaluate vertex signed distance.
   Only perfectly symmetric corners (Convex `BACK/BACK` or Concave `FRONT/FRONT`)
   are now permitted to chamfer in `BuildSurfaceAdjacencyGraph`.

H. ChopTjunctions Zipper Cascade Prevention
   Detail stairs touching the floor edge of a wall would trigger a vertical split.
   The next stair step would hit the new vertical split and trigger a horizontal split,
   zippering the entire wall into hundreds of triangles. Added `IsOriginalBrushEdge`
   check to `ChopTjunctions` so fragments (`parentSurfaceNum != -1`) only chop if
   touched along their original brush boundaries.

I. Transparent/Opaque Cross-Slicing Prevention
   Transparent surfaces (like water or glass) touching opaque structural walls would
   cause `ChopTjunctions` to slice the structural wall across its face. A check was
   added to ensure that a split is only allowed if both surfaces share the same
   translucency state (`CONTENTS_TRANSLUCENT`).
