# Technical Design & Study: `func_trisoup` Implementation

This document outlines the architecture, pipeline integration, and API constraints for implementing the new `func_trisoup` entity in the modernized BSP toolchain.

---

## 1. Context & Architectural Overview

The goal is to introduce `func_trisoup`, a brush-and-patch-based entity that:
1. Converts its non-caulk brush faces AND bezier patches into unified, smoothed `MST_TRIANGLE_SOUP` (trisoup) meshes.
2. Applies normal smoothing along shared edges based on a mapper-defined `shadeangle` threshold.
3. Automatically generates seamless lightmap UV coordinates via `xatlas` and optimizes geometry via decimation.
4. Perfectly respects lightmap density (`samplesize`) requirements for dynamically scaled UV allocations.

---

## 2. Detailed Technical Constraints of the Merging Pipeline

### The Promotion Solution for Brushes
Standard brush faces generated by the BSP compiler are stored as flat convex N-gons without index buffers. To enable merging these faces into a trisoup, we introduce a **promotion pass** (`PromoteBrushesToAtomicTrisoups`):
1. **Candidate Filtering**: Identify standard drawsurfaces within the `func_trisoup` entity using `IsChamferCandidate(ds)` (filters out water, fog, nodraw, sky, etc.).
2. **Triangulation**: Explicitly triangulate each flat N-gon face into a triangle fan.
3. **Flagging**: Set `ds->miscModel = qtrue` and `ds->planarDerived = qtrue` to mark them as promoted planar-derived trisoups.

### The Promotion Solution for Patches
Bezier patches are typically processed into triangle strips (`MST_PATCH`). To merge them into a trisoup, we process them via `PromotePatchesToTrisoups`:
1. **Subdivision**: Tessellate the control points into a grid using the entity's `subdivide` key.
2. **2-Pass Normal Generation**:
   * **Pass 1 (`MakeMeshNormals` on flat grid):** Computes normals on the raw subdivided grid *before* snapping to the curve. This preserves pristine edge-aligned normals matching adjoining brush geometry.
   * **Curve Snap (`PutMeshOnCurve`):** Deforms the mesh onto the Bezier surface.
   * **Pass 2 (`MakeMeshNormals` on curve):** Recomputes normals on the curve-fitted grid to capture the curvature and resolve collapsed poles.
   * **Normal Blending:** Preserves Pass 1 normals by default and only overrides vertices where Pass 2 diverges by more than ~41° (`DotProduct < 0.75f`). This prevents lighting seams where patches touch structural brushes.
3. **Triangulation**: Convert the 2D mesh grid into CCW winding triangles (`v0, v3, v2` and `v0, v2, v1`).
4. **Flagging**: Set `ds->miscModel = qtrue` and `ds->patchDerived = qtrue`.

## 3. Vertex Normal Smoothing by `shadeangle`

To achieve smooth Gouraud shading on curved structures (like columns or cylinders) while keeping sharp edges on flat intersections:
1. **Calculate Angle Threshold**: Read the `shadeangle` key from the entity (defaulting to e.g., $45^\circ$). Convert this to a dot product limit.
2. **Adjacency Check**: For any two surfaces sharing an edge:
   * Calculate the dot product of their face normals.
   * If the dot product is **greater than or equal to** $\text{threshold\_dot}$ (i.e., the angle between them is smaller than `shadeangle`), the edge is **smooth** and normals are blended.
   * Otherwise, the edge is **sharp** and normals remain unblended.

## 4. Pipeline Integration Plan

The `func_trisoup` compiler pass runs inside `ProcessWorldModel()` in `bsp.c` *before* the VIS data is extracted.

```c
// Process all func_trisoup entities as part of the world model!
for (int i = 1; i < num_entities; i++)
{
    entity_t *trisent = &entities[i];
    if (trisent->epairs && !strcmp(ValueForKey(trisent, "classname"), "func_trisoup"))
    {
        ProcessFuncTrisoup(trisent);
        FreeEpairs(trisent->epairs);
        trisent->epairs = NULL;
    }
}
```

The `ProcessFuncTrisoup` pipeline executes:
1. **PromotePatchesToTrisoups()**
2. **PromoteBrushesToAtomicTrisoups()**
3. **SmoothTrisoupNormalsByShadeAngle()**
4. **MergeAdjacentTrisoups()**
5. **DecimateAllTrisoups()**
6. **GenerateTrisoupUVs()**

## 5. Lightmapping Considerations & `samplesize`

When a surface is flagged as `miscModel = qtrue`, `AllocateLightmaps` naturally routes the surfaces to `AllocateLightmapForMiscModel(ds)`, which relies on the exact UV area generated by `GenerateTrisoupUVs` / `xatlas`.

### Minimum Scale Floor Bypass
The generic `AllocateLightmapForMiscModel` allocator traditionally forces standard imported meshes to consume a minimum `64x64` dimension block to prevent small meshes from becoming blurry. 
For `func_trisoup` surfaces, this minimum floor is explicitly bypassed if `ds->planarDerived` OR `ds->patchDerived` is true. This ensures that patch-based trisoups perfectly respect their physical density and `samplesize` scaling requirements, gracefully shrinking their lightmap footprint to 8x8 or 4x4 if requested, instead of artificially wasting lightmap packing space.
