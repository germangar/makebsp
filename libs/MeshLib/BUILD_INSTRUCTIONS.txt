================================================================================
MeshLib DLL Build Instructions for Windows (MinGW)
================================================================================

GOAL:
Build MeshLib's C API (MRMeshC) as a Windows DLL that can be linked from a
MinGW-based C project. We need MRMeshC.dll + an import library (.lib or .a)
that MinGW's linker can consume.

The project using this is compiled with:
  gcc/g++ from MSYS2 MinGW64 (GCC 10.3.0)
  Located at: E:/CODE/msys64/mingw64/bin/

The MeshLib source code is located at:
  e:\CODE\antigravity\makebsp\libs\MeshLib\

================================================================================
WHAT TO BUILD
================================================================================

We need two shared libraries (DLLs):

1. MRMesh.dll     — The core C++ mesh processing library
2. MRMeshC.dll    — The C-language bindings that wrap MRMesh

MRMeshC depends on MRMesh.

Source locations:
  MRMesh source:  libs/MeshLib/source/MRMesh/
  MRMeshC source: libs/MeshLib/source/MRMeshC/

================================================================================
BUILD CONFIGURATION
================================================================================

CMake defines to set:

  -DMRMESH_NO_OPENVDB=ON      # Disable OpenVDB support (not needed yet)
  -DMRMESH_NO_VOXEL=ON        # Disable voxel module (not needed yet)
  -DBUILD_SHARED_LIBS=ON      # Build as DLLs
  -DMRMeshC_EXPORTS=ON        # So MRMeshC exports its symbols

If the project has options for disabling Python bindings, tests, UI, or other
modules, disable them all. We only need the core mesh processing library
and its C API wrapper.

Compiler:
  Preferably MinGW g++ so the DLLs are ABI-compatible with our project.
  If MSVC must be used, we'll need a .def file or dlltool to create a
  MinGW-compatible import library from the MSVC .lib.

C++ Standard: C++20 (required by MeshLib headers — they check for it)

================================================================================
C API FUNCTIONS WE NEED (all from MRMeshC)
================================================================================

These are the specific functions our project calls. They are already declared
in the MRMeshC headers — we just need them compiled into the DLL.

From MRMesh.h:
  - mrMeshFromTrianglesDuplicatingNonManifoldVertices()
      Build a mesh from vertex coords + triangle indices.
      Automatically resolves non-manifold vertices by duplicating them.
  - mrMeshFindHoleRepresentiveEdges()
      Returns one edge per boundary hole in the mesh.
  - mrMeshPoints() / mrMeshPointsNum()
      Read vertex positions back from the mesh.
  - mrMeshGetTriangulation()
      Get triangle indices back from the mesh.
  - mrMeshFree()
      Deallocate a mesh object.
  - mrMeshPack()
      Pack mesh arrays after modifications.

From MRMeshBuilder.h:
  - mrMeshBuilderUniteCloseVertices()
      Welds vertices that are closer than a threshold distance.

From MRMeshFixer.h:
  - findAndFixMultipleEdges()
      Finds and resolves non-manifold (multiple) edges.
  - mrFixMeshDegeneracies()
      Fixes degenerate triangles and short edges.

From MRMeshFillHole.h:
  - mrFillHoles()
      Fills all holes given by their representative edge IDs.

From MRMeshDecimate.h:
  - mrDecimateMesh()
      Mesh decimation with configurable target error/face count.
  - mrDecimateSettingsNew()
      Get default decimation settings.

From MRMeshSave.h:
  - mrMeshSaveToAnySupportedFormat()
      Save mesh to .obj or other format by file extension.

From MRAffineXf.h:
  - mrAffineXf3fNew()
      Create identity transformation.

From MRMeshTopology.h:
  - mrMeshTopologyGetValidFaces()
      Get the set of valid faces.

From MRVector.h:
  - mrEdgePathFree() (for freeing the hole edge list)
  - mrTriangulationFree() (for freeing triangulation data)

================================================================================
OUTPUT REQUIREMENTS
================================================================================

After building, we need these files placed in a known location
(e.g., libs/MeshLib/build/Release/ or libs/MeshLib/bin/):

  MRMesh.dll          — Core library DLL
  MRMeshC.dll         — C API DLL
  libMRMeshC.a        — MinGW import library (or MRMeshC.lib if MSVC)
                         If only .lib is available, we can convert with:
                         dlltool -d MRMeshC.def -l libMRMeshC.a

The C headers are already in place at:
  libs/MeshLib/source/MRMeshC/*.h

These headers are what our project #includes. No changes needed to them.

================================================================================
HOW OUR PROJECT WILL LINK
================================================================================

In our Makefile we will add:

  CFLAGS  += -Ilibs/MeshLib/source/MRMeshC
  LDFLAGS += -Llibs/MeshLib/build/Release -lMRMeshC

At runtime, MRMeshC.dll and MRMesh.dll must be either:
  - Next to q3map.exe, OR
  - In the system PATH

================================================================================
THIRDPARTY DEPENDENCIES
================================================================================

MeshLib has thirdparty dependencies in libs/MeshLib/thirdparty/.
The ones likely needed for the core mesh module (no VDB/voxels):

  - eigen           (header-only, for math — likely bundled)
  - spdlog          (logging)
  - fmt             (string formatting, used by spdlog)
  - parallel-hashmap (header-only hash maps)
  - expected        (C++ expected/result type)
  - onetbb          (threading — may need to be built or skipped)

If TBB causes issues, check if MeshLib can be built single-threaded
or with TBB disabled.

================================================================================
SUMMARY
================================================================================

1. Configure with CMake, disable everything except MRMesh + MRMeshC
2. Build as shared libraries (DLLs) with MinGW g++ -std=c++20
3. Disable OpenVDB, voxels, Python, tests, UI
4. Place DLLs and import library in a known path
5. Our project will link with -lMRMeshC and include the existing C headers
